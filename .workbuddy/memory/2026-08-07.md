## P6-3a 灾难性坍塌根因（关键，避免重蹈）
- **根因不是「扩展数据」或「joint」，而是漏设 `KRONOS_DIRECTION_CLASS_WEIGHTS`**。翻阅 `outputs/models/` 下所有成功模型（r5_frozen_pool48 / r14_frozen_pool48_688169_only / r15_warmstart_r10_688169 / r16_return_head_only_r10）的 `summary.json`，**全部使用 `direction_class_weights=[2.0,0.5,2.0]`**；P6-3a 用了默认（None）→ 方向头在 3 类不平衡下坍缩到 FLAT，688169 真实评测 h=1/3/5/10 nonflat 仅 11/31/25/13%，全部垫底（基线 r10/r5 为 69/76/79/70%）。
- 无权重时训练期 val nonflat 跌到 ~7% 是**真实坍塌**（非 val/eval 分布错位）。
- **MultiHorizonForecastHead 架构与 pool_size 无关**：state_dict 只有 trunk(MLP)+return_head+ direction_head，没有 pool 相关参数（pooling 是前向时 mean/max 操作）。→ warm-start 头部可跨任意 pool_size 复用，无需匹配。
- 默认数据路径 `data/a_share_finetune_multiboard` 已指向重建的扩展数据集（train_end=2025-04-17 / val_end=2025-12-15），P6-3a 已用该数据。
